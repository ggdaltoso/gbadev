## When to use it

Transitions, mostly: entering a door, teleporting, a hit that blurs the screen for a moment. It's also a cheap way to hide a sudden change, because for a moment nobody can see the details.

## How to think about it

**Mosaic repeats pixels.** It picks one pixel, and draws it again in place of its neighbors, making a block. The hardware does it while drawing, so tiles don't change and it costs nothing to run.

	<svg viewBox="0 0 420 96" role="img" aria-label="Four 16 by 16 pixel patches of the same image. From left to right their blocks are 1, 2, 4 and 8 pixels wide, and the image gets coarser." style={{ display: 'block', width: '100%', maxWidth: '640px', marginInline: 'auto' }}>
		{blocks.map((block, column) => (
			<g key={block} transform={`translate(${column * 105 + 4} 2)`}>
				{Array.from({ length: 16 * 16 }, (_, i) => {
					const x = i % 16, y = Math.floor(i / 16);
					const sx = x - (x % block), sy = y - (y % block);
					const inside = (sx - 7.5) ** 2 + (sy - 7.5) ** 2 < 36;
					const edge = (sx - 7.5) ** 2 + (sy - 7.5) ** 2 < 56;
					return <rect key={i} x={x * 5} y={y * 5} width="5" height="5" fill={inside ? '#f2c94c' : edge ? '#c98a2b' : '#3abe41'} />;
				})}
				<text x="40" y="92" font-size="10" text-anchor="middle" fill="currentColor">{block} px</text>
			</g>
		))}
	</svg>
	<figcaption>The same 16x16 patch with bigger and bigger blocks. Each block takes the color of its top left pixel.</figcaption>
</figure>

**Stretch goes from 0 to 1.** 0 is normal, and 1 makes blocks of 16 pixels. The hardware has 4 bits for each direction, so there are 16 sizes, and a slow change moves in steps.

**Backgrounds and sprites have their own settings.** `bn::bgs_mosaic` and `bn::sprites_mosaic` work separately, each with a horizontal and a vertical stretch. Setting one doesn't touch the other.

**You choose what takes part.** Call `set_mosaic_enabled(true)` on each background or sprite. Everything else stays sharp.

## The smallest thing that works

Press **A**, and the hero teleports: the picture gets blurrier, the hero jumps at the blurriest moment, and it sharpens again. The text has no mosaic enabled, so it stays readable.

## Pitfalls

**Nothing happens.**
You set the stretch, but nothing has mosaic enabled, or you set the wrong side: `bgs_mosaic` doesn't move sprites.

**The background is blurry but the sprite isn't.**
Set both, and enable it on both, as the snippet does.

**Sprites and background don't line up while blurred.**
They have separate grids of blocks, and a sprite's starts at the sprite. Hide it, or keep the moment short, and nobody will notice.

**The picture stays a little blurry.**
The stretch didn't get back to 0. Make the last step exact, as `frames_from_middle` does here.

**A fixed-speed change looks uneven.**
Going from 1 to 2 pixels looks like a bigger change than from 15 to 16. Short transitions hide it.
