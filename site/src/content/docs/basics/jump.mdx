export const heightAt = (frame) => Math.max(0, 4 * frame - 0.125 * frame * (frame - 1));
export const airFrames = 32;
export const peak = Math.max(...Array.from({ length: airFrames + 1 }, (_, n) => heightAt(n)));
export const arc = Array.from({ length: airFrames + 2 }, (_, n) => n);
export const sideX = (frame) => 30 + frame * 4.2;
export const sideY = (z) => 110 - z * 2.2;
export const topFrames = [0, 6, 16, 26, 33];
export const shadowFrame = (z) => (z < 10 ? 0 : z < 22 ? 1 : 2);
export const shadowBands = [
	{ from: 0, to: 9, frame: 0 },
	{ from: 10, to: 21, frame: 1 },
	{ from: 22, to: peak, frame: 2 },
];
export const bush = 12;
export const bumps = (ahead) => {
	let z = 0, speed = 4, distance = 0, bump = false;
	for (let frame = 0; frame < 60; frame++) {
		z += speed;
		if (z > 0) { speed -= 0.25; } else { z = 0; speed = 0; }
		distance += 2;
		if (Math.abs(ahead - distance) < 12 && z < bush) { bump = true; }
	}
	return bump;
};
export const clears = Array.from({ length: 60 }, (_, i) => 12 + i * 2).filter((ahead) => !bumps(ahead));
export const above = arc.filter((n) => heightAt(n) >= bush);
export const overlapFrames = Array.from({ length: 12 }, (_, i) => -10 + i * 2).filter((ahead) => Math.abs(ahead) < 12).length;

## When to use it

When the camera looks down on the ground, and something has to leave it: a runner that jumps over logs, a top-down hero hopping a gap, a ball bounced in a sports game, a grenade thrown in an arc. Seen from above, up and forward are the same direction on the screen, so a jump needs its own number, and a shadow to show where on the ground the jumper is.

A side view doesn't need any of this: there, the screen's y is the height. See [Gravity and jumping](/math/gravity/).

## How to think about it

**Height is a third axis.** The hero has a place on the ground, x and y, and a height above it, z. Gravity, as on the [Gravity and jumping](/math/gravity/) page, only changes z: A gives it a speed of 4 pixels a frame upward, and every frame 0.25 is taken off that speed. The place on the ground keeps running as before. Only the drawing mixes them: the hero is drawn at `hero_y - z`, z pixels up the screen from its place on the ground. The jump lasts {airFrames} frames and goes {peak} pixels high.

**The shadow stays on the ground, smaller the higher the hero is.** The shadow is drawn at the hero's place on the ground, so while the hero rises, the shadow doesn't move, and the gap between them is the height. That gap alone could also be the hero walking up the screen; the shadow's size settles it. It's three frames of the same oval, 14, 10 and 6 pixels wide, picked from z. Scaling one oval with an affine sprite would also work, but would spend one of the 32 affine matrices on it.

**A bump needs the hero in the way and low enough.** On the ground, the test is the one from [Endless run](/basics/runner/): the obstacle and the hero's place on the ground less than 12 pixels apart, in the same lane. The jump adds one more condition: z under the obstacle's height. A bush is {bush} pixels tall. The jump is over {bush} pixels for {above.length} of its {airFrames} frames, and the bush overlaps the hero's place for {overlapFrames} of them, so A can come early or late. Played out frame by frame, pressing A when the bush is anywhere from {clears[0]} to {clears[clears.length - 1]} pixels ahead clears it: {clears.length} frames to choose from.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `constexpr int heights[] = { 12, 8, 14 };` | Data indexed by the obstacle's frame in `obstacles.bmp`: the same `kind` picks the picture and the height. |
| `obstacle{ sprite, random.get_int(3), next_obstacle, heights[kind] }` | Aggregate initialization, in member order. The height is copied in, so the obstacle doesn't need to remember its kind. |
| `if(z == 0 && bn::keypad::a_pressed())` | Only from the ground. `z` is set back to exactly 0 on landing, so comparing a `bn::fixed` with `==` is safe here. |
| `z < 10 ? 0 : z < 22 ? 1 : 2` | Two conditional operators chained: they read top to bottom like an `if` / `else if` / `else`, and give a value. |
| `hero.set_z_order(-1);` | A lower `z_order` is drawn in front. Without it the obstacles, made later, would be drawn over the hero. See the pitfalls. |

## Pitfalls

The test ROMs for these put every obstacle in the middle lane and pressed A on their own when the next one was 30 pixels ahead, so each run was the same.

**The shadow rises with the hero.**
The guide's shared hero has a shadow drawn into its art, under the boots. A test ROM that jumped with it and hid the snippet's shadow showed that patch going up the screen with the hero, and nothing left on the ground to say where it was. Draw the shadow as its own sprite, and use art without one: here, the `bare_hero` of [Shadows and reflections](/effects/shadows/).

**The hero bumps into an obstacle it has already jumped over.**
A test ROM tested the bump with where the hero is drawn, `hero.y()`, and without the height. Every jump in it counted a bump, and the HUD showed when: with the obstacle already 18 pixels behind the hero's place on the ground, and the hero 27 pixels up, on the way down. Drawn 27 pixels up the screen, it met an obstacle that had passed under it. The snippet, pressing A at the same moment, counted none in 7 seconds. Test with the place on the ground, `hero_y`, and the height on its own.

**The obstacle is drawn over the hero jumping it.**
On a tie, the newest sprite is drawn on top, and the obstacles are made after the hero. A test ROM without `hero.set_z_order(-1)` drew the bush over the hero's legs while the hero was over it. With it, the hero is in front: a hero in the air is closer to the camera than anything on the ground. On the ground, a bush below the hero should cover it instead; [Depth sorting](/basics/depth/) does that by y.

**The shadow cuts a hole in an obstacle.**
Blending mixes a sprite with the layer behind it, and for a sprite that's a background: two sprites don't mix. A test ROM with the shadow in front of the obstacles showed it, as the bush passed the shadow, as a patch of darkened dirt in the middle of the bush, not a darker bush. The snippet keeps the shadow behind the obstacles with `shadow.set_z_order(1)`, so an obstacle hides it.
