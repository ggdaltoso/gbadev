## When to use it

When the world changes in play and the change stays: a crate pushed, a wall knocked down, a door that opens for good, a bridge built, grass cut. Changes that are too many for sprites, or that should stay in the level like the rest of it. The background is a map of cells, and the code can write those cells while the game runs.

This page pushes barrels through the garden of [Grid-locked movement](/basics/grid/). To build a whole map from code once, see [Cave generation](/math/cave/); to animate tiles that don't move, [Animated tiles](/effects/tiles/).

## How to think about it

**Two copies of the level, changed together.** The rules read `level`, one character per 16x16 cell. The screen shows the background map, four 8x8 map cells per level cell, each holding the number of a tile. They must always agree, or the hero walks through a barrel that's drawn, or stops in front of one that isn't. So the snippet changes the level in one place only, `put`: it writes the character, then the four map cells. The map draws no art of its own: it only points at the 20 tiles of the tileset, four per kind of cell.

**The screen shows a copy, and the copy is made only when asked.** The map cells the code writes are in RAM. What the GBA draws is a copy of them in video memory, and writing the RAM doesn't touch it. `reload_cells_ref` asks Butano to copy the whole map again, all 1024 cells, on the next `bn::core::update()`. Calling it twice in one frame still makes one copy: Butano's source only marks the map to be copied. So `put` can call it every time, and a frame that changes three cells costs the same as one.

**Map cells change a whole cell at a time, so a moving barrel is a sprite.** A tile can't be drawn 2 pixels to the side. So when a push starts, `put` takes the barrel out of the map and a barrel sprite takes its place, on the same pixels. The sprite moves with the hero, 2 pixels a frame, and when the hero reaches its cell, `put` writes the barrel back into the map, one cell further, and the sprite hides. One sprite is enough, however many barrels there are: only one moves at a time.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `char level[rows][columns + 1] = { "###...", ... };` | An array of arrays of `char`, so the game can write it. Each row copies its string, `'\0'` included: hence `columns + 1`. The `const char*` level of [Grid-locked movement](/basics/grid/) points at text in ROM, which can't be written. |
| `auto put = [&](int x, int y, char kind) { ... };` | A lambda kept in a variable: a small function inside `main`. `[&]` lets it use `main`'s variables, here `map` and `bg_map`, by reference. |
| `bn::unique_ptr<garden_map> map(new garden_map());` | The map's 1024 cells live on the heap, as in Butano's own example, and are freed when `map` goes away. |
| `part % 2`, `part / 2` | The four map cells of a level cell, numbered 0 to 3 as in the tileset: the remainder is the column, the division the row. |
| `kind == '#' ? bush_tiles : kind == 'o' ? barrel_tiles : ...` | Two `?:` in a row, read as "if, else if, else". |

## Pitfalls

**The hero walks through a barrel.**
A test ROM without the `reload_cells_ref` call changed the level and the map cells in RAM, but never sent them to the screen. Pushed from the left, the barrel at (3, 1) stayed drawn where it was, the sprite slid away from it and vanished on arrival, and the hero walked into the drawn barrel's cell and on through it: for the rules, it was grass. The real barrel, at (5, 1), wasn't drawn at all.

**Two barrels become one.**
A test ROM that only checked the cell behind the barrel for a bush, `!= '#'`, let the hero push the barrel at (11, 8) into the one at (10, 8). `put` wrote an `o` over an `o`, and the row that had two barrels had one. The snippet only pushes into grass, `== '.'`, so a barrel is a wall for another barrel.

**The barrel runs ahead of the hero.**
A test ROM that wrote the barrel into its new cell as the push started, with no sprite, made it jump a whole cell at once. Pushing right, there was a cell of grass between the hero and the barrel for most of every step, until the hero caught up and the barrel jumped again. In the snippet, the sprite stays against the hero all the way.
