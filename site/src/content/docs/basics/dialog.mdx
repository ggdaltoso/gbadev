## When to use it

When a character has more to say than fits in a corner of the screen: a villager, a sign, a tutorial, a story between levels. The player reads at their own pace and presses a button to go on.

For a score or a timer that's always on screen, see [the HUD page](/basics/hud/). This page builds on its font and text generator.

## How to think about it

**Letter by letter is one counter.** The page doesn't keep a growing string. It keeps `shown`, how many characters are visible on this page, and adds 1 every 2 frames. Each row shows as many of them as it can, and the rest go to the next row. A row is only rebuilt when its count changes, so while one row grows, the others stay as they are:

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `constexpr bn::string_view villager_text = "Hi there! ..." "morning, ..."` | Two string literals side by side are joined into one by the compiler, so a long text can span lines. A `bn::string_view` of a literal costs nothing: the text stays in the ROM. |
| `bn::vector<bn::string_view, 12> lines` | Each line is a view into `villager_text`: a pointer and a length, no copy. That's safe because the literal lives as long as the game. A view into a `bn::string` that's gone would point at garbage. |
| `text.remove_prefix(...)` | Moves the view's start forward. `wrap` eats the text from the front until nothing is left. |
| `bn::vector<bn::sprite_ptr, 8> line_sprites[lines_per_page]` | An array of three vectors, one per row, so each row can be cleared and rebuilt on its own. |
| `int row_shown[lines_per_page] = {};` | The empty braces set every element to 0. Without them, a local array starts with whatever was in memory. |
| `BN_ASSERT(end > 0, "A word is wider than the box")` | A check that stops the game with a clear message, instead of letting the bug show up somewhere else. |

## Pitfalls

**One press opens the box and skips the first page.**
If opening the box and handling the box are two `if`s one after the other, the same **A** press reaches both. In a test ROM written that way, the box opened and went straight to page 2: on the opening frame nothing was shown yet, so the page counted as complete, and **A** turned it. The snippet uses `if(talking) ... else ...`, so each press is handled once.

**Rebuilding every row on every frame.**
Making text sprites is the expensive part of text. Rebuilding all three rows on every frame of typing peaked at 66.63% of a frame in a test ROM. Rebuilding only the row that changed peaked at 27.17%. Rebuild when the count changes, and only where it changes.

**"Day 1/3" shows as "Day 13".**
This font has no `/`, and its width table in `font.h` says 0 for it, so the generator skips it without an error. Check the text against the characters your font has, especially numbers and punctuation.

**"Vector is full" when a word doesn't fit.**
A word wider than the box has no space to break at. Without the `BN_ASSERT`, a test ROM's `wrap` kept adding empty lines, one per character it dropped, until the 12 lines were used up and `bn_vector.h` stopped the game. The assert names the real problem. If your texts come from players or translators, break inside the word instead.
