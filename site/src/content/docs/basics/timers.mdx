## When to use it

Timers, whenever something should happen later or last a while: a power-up for 10 seconds, an enemy every half second, a blink before something disappears. Random numbers, whenever the game shouldn't be the same every time: where things appear, what drops, which way an enemy turns.

## How to think about it

**A timer is a frame counter.** The game loop runs once per frame, about 60 times per second, so time in a game is a number of frames. Set a counter, subtract 1 every frame, and act when it reaches zero. 60 frames is about one second, 30 is half a second.

**Each thing keeps its own counter.** A coin that disappears after 2 seconds carries its `frames_left`. There is no global clock to ask; every countdown is a plain `int` next to the thing it times.

**Frame time stops when the game stops.** If you skip updating the counters, during a pause for example, they wait. That's usually what a game wants. For real time, like measuring how long your code takes, there's `bn::timer`, which counts hardware ticks whether the game is paused or not.

**Random numbers come from a formula.** The GBA has no source of randomness. A generator takes a number, the seed, and turns it into a sequence that looks random. Butano has two:

- `bn::random`, which starts from a fixed state. Call `update()` every frame so that its state depends on how long the game has run.
- `bn::seed_random`, whose seed you set and read back. The snippet uses this one.

**The same seed gives the same sequence.** Every time, on every GBA and emulator. That's a feature: store the seed and you can replay a whole game, reproduce a bug, or give everyone the same daily challenge.

**Seed with something the player does.** Every power-on starts from the same state, so the seed must come from outside the game. Counting frames until the player presses START works: no one presses it on the same frame twice.

**`get_int(limit)` goes from 0 to `limit - 1`.** `get_int(15)` picks one of 15 columns, 0 to 14. `get_int(20, 60)` goes from 20 to 59.

## Pitfalls

**The game is the same every time you turn it on.**
The generator starts from the same state at every power-on. Seed it from the player, as above. With `bn::random`, call `update()` every frame, including on the title screen.

**Two games look almost the same.**
`bn::seed_random` adds 1 to its seed for every number it gives, so seed 138 gives the sequence of seed 137 shifted by one. Two players who pressed START one frame apart get nearly the same game:

| Seed | First eight `get_int(15)` |
|---|---|
| 137 | 14, 4, 7, 2, 7, 5, 13, 4 |
| 138 | 4, 7, 2, 7, 5, 13, 4, 6 |
| 137 × 2654435761 | 1, 2, 3, 8, 6, 0, 3, 3 |
| 138 × 2654435761 | 14, 4, 11, 4, 12, 11, 3, 13 |

Multiplying the count by a big odd number, as the snippet does, puts close counts far apart.

**A die never rolls 6.**
`get_int(6)` goes from 0 to 5. Use `get_int(1, 7)`.

**A countdown of 33 waits 34 frames.**
The frame that sets the counter, plus 33 frames counting down to 0, and the spawn happens on the next one. That's why the timeline above has a gap of 34 after a wait of 33. It rarely matters, but pick one convention and keep it.

**One second of frames isn't one second.**
The GBA draws 59.73 frames per second, so 60 frames last a bit more than a second, and a clock made of frames runs about 16 seconds late per hour. Fine for gameplay; for a real clock, use `bn::timer`.

**A replay goes wrong after you change unrelated code.**
Every number depends on how many came before it. One extra `get_int`, anywhere, shifts everything after it. When replays matter, draw numbers in a fixed order, or keep a separate generator for things that don't affect the game, like particles.
