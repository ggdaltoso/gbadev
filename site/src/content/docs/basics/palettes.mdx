## When to use it

Whenever you care about color, which is always: importing art, transparency, and every effect that changes colors on screen. Recoloring is the cheapest effect the GBA has. It never touches a tile, so it costs the same for one pixel or the whole screen.

## How to think about it

**Pixels store an index, not a color.** A 4bpp tile pixel is a number from 0 to 15, and the palette says which color each number is. Change color 3 of a palette, and every pixel with index 3, in every tile that uses that palette, changes in the same frame.

**A color has 15 bits: 5 per channel.** `bn::color(r, g, b)` takes values from 0 to 31, so pure red is `bn::color(31, 0, 0)`. From the usual 0 to 255, divide by 8: `(90, 174, 228)` becomes `bn::color(11, 21, 28)`. The 3 lowest bits are lost, so colors closer than 8 apart become the same color on the GBA.

**There are 16 palettes of 16 colors for backgrounds, and another 16 for sprites.** A 4bpp image uses one of them; an 8bpp image uses all 256 colors of its side as one big palette. When an item is created, Butano looks for an identical palette already in use and shares it, so a `bn::bg_palette_ptr` or `bn::sprite_palette_ptr` may belong to more than one thing.

**Index 0 is never drawn.** Whatever color the image has there, index 0 is a hole (see [backgrounds](/basics/backgrounds/#how-to-think-about-it) and [sprites](/basics/sprites/#pitfalls)). Pick a color the art never uses, like magenta, so mistakes show.

**Four ways to change colors without touching tiles.** All of them are methods of the palette, and most have [actions](https://gvaliente.github.io/butano/group__action.html) that animate them:

| Method | What it does |
|---|---|
| `set_color`, `set_colors` | Replaces one color, or all of them, for example from another palette item. |
| `set_fade` | Mixes every color with one color: 0 is the original, 1 is that color. |
| `set_grayscale_intensity`, `set_inverted`, `set_hue_shift_intensity` | Ready-made filters, with the same 0 to 1 intensity. |
| `set_rotate_range`, `set_rotate_count` | Rotates a range of colors: each index shows the color of its neighbor. |

`bn::bg_palettes` and `bn::sprite_palettes` have the same effects for all palettes of a side at once, which is how you fade the whole screen.

## Pitfalls

**Two colors that were different in the image look the same.**
5 bits per channel: colors less than 8 apart in every channel become one. Compare colors after dividing by 8, not in your editor.

**Changing one thing's colors changes another thing too.**
They share the palette, because Butano gives identical palettes to the same `bn::sprite_palette_ptr` or `bn::bg_palette_ptr`. A palette effect applies to everyone that uses it. For the whole side, use `bn::bg_palettes` or `bn::sprite_palettes` instead.

**Pixels that shouldn't move are blinking.**
They use an index inside the rotation range. An image editor reuses an index for every pixel of the same color, so if the banks and a water stripe share a color, the banks rotate too. Give the pixels that must stay put their own index, even with a duplicated color. The tool for this snippet does exactly that.

**"Invalid delta count", or the rotation wraps at the wrong place.**
`bn::bg_palette_rotate_by_action` reads the range size when it's created. Call `set_rotate_range` first, then create the action, as the snippet does.

**The backdrop isn't the color at index 0.**
Index 0 is never drawn, in any palette. The color behind every layer comes from `bn::bg_palettes::set_transparent_color`.

**Colors of an 8bpp image change when another one appears.**
All 8bpp images of a side share the one 256-color palette. See [backgrounds](/basics/backgrounds/#pitfalls).
