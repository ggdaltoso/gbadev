## When to use it

As soon as your game has more than one screen: a title, a level, a game over. Without some structure, `main` turns into one loop full of `if(on_title)`, and every sprite has to be hidden by hand when the screen changes.

## How to think about it

**A scene is a function with its own loop.** It creates what it needs, runs until it's done, and returns which scene comes next. `main` only calls whichever one was returned.

**C++ does the cleanup.** A `bn::sprite_ptr` or `bn::regular_bg_ptr` releases its memory when it's destroyed. Local variables are destroyed when the function returns, so a scene can't forget anything on screen, and the next one starts with all the room it needs.

**What has to survive lives in `main`.** The score outlives the scene that counted it, so it's declared outside and passed by reference. If it's in a scene, it's gone when that scene ends.

**The screen doesn't reset by itself.** Fades belong to the palettes, not to a scene. A scene that ends in black leaves the next one black, until something fades it back in.

## Pitfalls

**A scene gets skipped.**
`a_pressed` stays true until the next `bn::core::update()`. If one scene ends on **A** and the next one reads **A** before any update, it sees the same press. Here the fades run updates in between, so it doesn't happen. Without them, call `bn::core::update()` before returning.

**"no matching function for call to 'bn::sprite_ptr::sprite_ptr()'".**
A `bn::sprite_ptr` always holds a real sprite, so a class member has to be created in the constructor's initializer list, as `hero` does. If it should only exist later, use `bn::optional<bn::sprite_ptr>`.

**A white screen, and `main` never runs.**
A global `bn::sprite_ptr` is created before `main`, so before `bn::core::init()`. Create Butano objects after that call, which is another reason to keep them inside scenes.

**The screen stays black after a scene change.**
The last scene faded out and nothing faded back in. Every scene here starts with `fade_to(0)`. If you add a scene, it needs one too.

**"switch missing default case".**
Butano builds with `-Wswitch-default`, so the warning appears even when all enum values are covered. Add a `default`, as `main` does here.

**Something from the last scene is still on screen.**
It's declared outside the scene, in `main` or as a global, or the scene's function hasn't returned. Keep it local.
