## When to use it

When danger comes on a timetable: lasers that fire across a corridor, rocks that fall from the ceiling, a boss attack, a train in a runner, a wave of enemies in a shooter. The player should see it coming, so every hazard first warns, with a blink, a sound or a shadow, and only then hurts.

One hazard on its own is a [state machine](/structure/states/), and a fixed sequence of things that happen one after the other is a [scripted cutscene](/structure/cutscene/). This page is for many hazards that overlap, each running its own warning, started by a schedule.

## How to think about it

**A hazard's phase comes from its age.** Each beam only counts the frames since it started. Under 60 it's warning: its target blinks on the ground and nothing hurts. From 60 to 79 it's active: the beam is shown and it hurts. At 80 it's over and goes away. No flag says "warning" or "active": the age decides, so the phases can never disagree with each other.

**The schedule is data, read in order.** The level's rhythm is a table: when each beam starts, in frames, and where. The game keeps a frame count and the index of the next row. Every frame, it starts each row whose time has come and moves the index past it, so the table must be sorted by time. Changing the level means changing numbers, and the loop doesn't change. When the frame count reaches the end of the loop, both go back to 0 and the table plays again.

**A fair warning is longer than the way out.** A beam hurts the player when their centers are less than 12 pixels apart, and the player walks 2 pixels a frame. Standing right under a beam, getting out takes 12 / 2 = 6 frames. The warning lasts 60, so the other 54 are time to notice the target, hear the beep and decide which way to go. Shorten the warning toward 6 frames and the beams stop being dodgeable and become luck.

## The smallest thing that works

Walk with **←** and **→**. A target blinks on the ground and a beep plays: a beam lands there one second later. Being under a beam while it's active counts a hit, and the player blinks for a moment in which beams don't hurt. The schedule plays again every 400 frames.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `constexpr scheduled_beam schedule[] = { { 0, -60 }, ... };` | The level as data: an array of aggregates, built when compiling, one row per beam. |
| `sizeof(schedule) / sizeof(schedule[0])` | The number of rows of a plain array: its size in bytes over one row's. It updates itself when rows are added. |
| `beams.push_back(beam{ x, 0, bn::sprite_items::target.create_sprite(...), ... });` | Aggregate initialization with sprites inside: they're made right there, in member order. `bn::sprite_ptr` has no default constructor, so they can't be left out. |
| `bool active = ! warning && falling.age < warning_frames + active_frames;` | The phase, worked out again every frame from the age. |
| `bn::sound_items::beep.play();` | Played where the beam starts, which happens once per beam. Inside the per-frame loop it would play again every frame. |
| `bn::erase_if(beams, [](const beam& done) { ... });` | Removes the beams that are over, and their sprites with them. See [Game objects](/structure/objects/). |

## Pitfalls

**A beam comes late.**
The next-row index only looks at the row it points to. In a test ROM whose table had the beam planned for frame 100 written after the one at 130, the one at 100 waited behind it and started at 130, together with the other: 30 frames late and on top of another hazard. Keep the table sorted by time, or check every row each frame if it's short.

**The player gets hurt by the warning.**
In a test ROM that checked the hit in every phase, standing where the first beam would fall counted a hit at age 0: the frame the target appeared, a second before the beam. Hurt only in the active phase, as the snippet's `active &&` does.

**Some beams never start.**
Starting a row when the frame count is exactly its time works only if the count passes through every number. In a test ROM whose clock went up by 1.5 per frame, a fast mode, comparing with `==` started 7 of the 10 beams in each loop. The clock read 49.5 and then 51, so 50 was never its value; by the same arithmetic 230 and 320 were skipped too. Start a row when its time is less than or equal to the clock, as the snippet's `<=` does, and move past it.
