export const won = [1, 3, 2, 2, 0, 0];
export const needed = [0, 1, 3, 5, 8, 11];
export const total = won.reduce((sum, coins) => sum + coins, 0);
export const cellX = (level) => 130 + level * 40;

## When to use it

When a game has levels the player picks: a puzzle game with a hundred boards, a set of stages, a world map of missions, the minigames of a party game. The menu has to say three things at a glance: which levels can be played, how well each one went, and what's still missing to open the next.

This menu opens levels by coins won in all. The same shape works for any goal: stars, a score, beating the level before.

## How to think about it

**The menu draws the progress, and locks are worked out from it, never kept.** The only thing the game remembers is `coins_won`, the best result in each level. A level is open when the coins in all reach its goal in `coins_needed`, and `unlocked` works that out every time it's asked. There's no list of open levels to keep up to date, so the menu can't show a lock that the coins already opened. `draw` makes the whole menu again from those numbers each time they or the cursor change.

**The cursor goes everywhere, and a locked level shows what's missing.** Skipping locked levels would hide the one thing the player wants to know about them. So the cursor can stop on any level, and the line at the bottom changes: on an open level it shows the coins won and that **A** plays it; on a locked one, how many more coins it needs, `coins_needed[selected] - total_coins()`. The goal is a subtraction, not a message written by hand for each level.

**The lock is checked where a level starts, not only drawn.** A lock on the screen is only a picture. What keeps a locked level closed is the test before it starts: **A** plays the selected level only if `unlocked(selected)`. Drawing and starting ask the same function, so they always agree.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `int coins_won[levels] = {};` | Empty braces set every element to 0. |
| `for(int coins : coins_won)` | A range-based `for` over a plain array: the compiler knows its size. |
| `level % columns`, `level / columns` | A level's column and row in the grid, from its number. `row * columns + column` goes back. |
| `missing == 1 ? "" : "s"` | "1 more coin", "5 more coins". |
| `changed = changed \|\| new_column != column \|\| new_row != row;` | The menu is only drawn again on the frames something changed: making its sprites every frame would be wasted work. |

## Pitfalls

**The lock stays after the goal is met.**
A test ROM that worked out which levels were open once, at the start, and kept them in an array, never opened level 2. After the first coin, the box still showed the lock, the line at the bottom, which counts the coins itself, said "Level 2: 0 of 3 coins. A: play", and **A** did nothing. Two answers to one question disagreed. Work the lock out from the coins every time.

**Locked levels can be played.**
A test ROM that drew the locks but didn't check them when **A** was pressed let the cursor go to level 3, still locked, and win all three of its coins. That opened levels 2 and 3 without level 1 or 2 ever being played: the lock had only been a picture.

**One step past the last level stops the game.**
A test ROM that moved the cursor as one number, `+ 1` for right and `+ 3` for down, with no limits, went from level 6 on to a level 7 that doesn't exist. There, the bottom line was built from numbers read past the end of `coins_needed` and `coins_won`, and the game stopped on Butano's error screen: "String is full". Keep the column and the row inside the grid.
