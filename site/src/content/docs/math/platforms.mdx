## When to use it

When a level has more than solid blocks: thin planks the player jumps up through from below and stands on from above, platforms that slide across a pit, elevators. They make levels feel built instead of carved, and they're everywhere in platformers. Both are small rules on top of the block collision of [Forgiving jumps](/math/forgiving/).

## How to think about it

**A one-way surface only stops feet that were above it.** A plank isn't part of `hits`, so heads and sides go through it. It only matters to a falling player, and only when the feet were on or above its top last frame and are on or below it now: `lands(top, old_feet, new_feet)`. Rising through it changes nothing, and a fall that starts below the top falls on through.

**A moving platform carries whoever stands on it by exactly what it moved.** Each `mover` keeps this frame's move in `moved_x` and `moved_y`. The player remembers which one it stood on last frame, `riding`, and gets that move added to its position before anything else. Carried that way, the player stays put on the platform, can walk on it, and moves with it on both axes: across the pit and up the elevator. Landing on a mover uses the same one-way rule as the planks.

**Platforms move first, then the player.** The loop moves every platform, then carries the player, then reads the keys and does the player's physics against where the platforms already are. Everything the player is tested against is in its final place for this frame, so the feet end exactly on the top, frame after frame.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `int wait = 0;` inside `mover` | A default for that member. `{ sprite, 1, 0, -36, 36 }` lists the first five, and the rest keep their defaults. |
| `[[nodiscard]] int top() const` | A member function that reads the platform without changing it, so it can be called on a `const mover&`. |
| `for(int side_x : { (x - 7).floor_integer(), (x + 6).floor_integer() })` | The same test for the left and the right foot, from a list written in place. |
| `const char* on = riding >= 0 ? ... : ...;` | Chained `?:`: the first condition that holds picks the text. |
| `if(on != shown)` | Compares the pointers, not the letters. It works here because each text is one string literal, which always has the same address. |

## Pitfalls

**The platform slides out from under the player.**
A test ROM that didn't carry the rider got the same keys as the snippet: walk onto the red platform while it rests at the pit's edge, then wait. When the platform left, the player stayed where it was, the platform's edge passed under its feet, and it dropped into the pit and started over. The snippet rode it across.

**The player floats above or sinks into the elevator.**
A test ROM that moved the platforms after the player, starting on the elevator, put the feet on the top where the elevator was, and then the elevator moved. On the way down, the feet stayed 1 pixel above it; on the way up, 1 pixel into it; resting, in place. In the snippet, measured the same way on the same frames, the feet never left the top.

**A plank that's solid can't be jumped through.**
A test ROM that treated the planks as blocks bumped the player's head on the plank's underside, from the same spot and the same jump that took the snippet up through it, and dropped it back on the ground.
