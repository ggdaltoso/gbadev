## When to use it

Whenever two moving things can touch: the hero and an enemy, a shot and a target, the hero and a coin. For the hero against walls and water, [map collision](/basics/collision/) checks cells instead.

## How to think about it

**A hitbox is a rectangle that stands in for a thing.** The game never asks whether two pictures touch, only whether two rectangles overlap. That's four comparisons, cheap enough to do for every pair of things on screen.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `constexpr box_shape hero_tight = { ... }` | The shapes never change, so they're built while compiling and cost nothing at run time. |
| `hitbox()` returns a new `bn::fixed_rect` | The box is worked out from the sprite every time, so it can't be left behind when the sprite moves. |
| `bn::optional<bn::sprite_ptr> _outline` | A sprite that may not exist. `reset()` destroys it, and `->` reaches it when it does. |
| `const box_shape& _shape() const` | Returns a reference to one of the two members, not a copy, and the `const` promises it doesn't change the object. |

## Pitfalls

**Things collide with space between them.**
The box is the size of the sprite, not of the art. In the diagram, there are four pixels of grass between the log and the hero, and the 32x32 boxes overlap by four rows. Measure the art and use tight boxes.

**One touch counts as many hits.**
Overlap lasts many frames, and the check runs every frame, so without anything else a touch counts once per frame. Give the hero a few safe frames after a hit, as the snippet does with `safe_frames`, or remove the thing that hit, as the coins do by jumping somewhere else.

**The box is half its size off.**
`bn::fixed_rect` takes the center. A 16x16 box at (0, 0) goes from -8 to 8. If you pass a top-left corner, the box sits up and to the left of the art. For a top-left corner, use `bn::top_left_fixed_rect`.

**Boxes that only touch don't intersect.**
Two 16x16 boxes side by side, edge on edge, gave `intersects` false and `touches` true. Use `touches` if sharing an edge should count.

**A fast shot passes through.**
A 4x4 shot moving 20 pixels per frame jumped over an 8-pixel-wide wall without ever overlapping it: 0 hits in 11 steps. Make the box at least as long as the step, or split the move into smaller steps.

**`bn::rect` with an odd size.**
The integer version has no half pixels: a `bn::rect` of width 5 gave `left()` -2 and `right()` 2, four pixels apart. Use even sizes, `bn::fixed_rect`, or `bn::top_left_rect`, as Butano's header suggests.

**The game slows down with many things.**
Every shot against every enemy is a lot of pairs. See [the performance page](/structure/profiler/) for a loop like that, measured and fixed.
