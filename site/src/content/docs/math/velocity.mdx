export const grass = { name: 'Grass', max: 1.5, acceleration: 0.125, friction: 0.0625, color: '#1e7cb8' };
export const sand = { name: 'Sand', max: 0.75, acceleration: 0.0625, friction: 0.25, color: '#2f9e36' };
export const approach = (value, target, step) => (value < target ? Math.min(value + step, target) : Math.max(value - step, target));
export const simulate = (surface, pushFrames, totalFrames) => {
	let speed = 0;
	let position = 0;
	const frames = [];
	for (let frame = 0; frame < totalFrames; ++frame) {
		const pushing = frame < pushFrames;
		speed = approach(speed, pushing ? surface.max : 0, pushing ? surface.acceleration : surface.friction);
		position += speed;
		frames.push({ frame, speed, position, pushing });
	}
	return frames;
};

export const naive = (() => {
	let speed = 4320 / 4096;
	const values = [];
	for (let frame = 0; frame < 40; ++frame) {
		speed = speed > 0 ? speed - 0.0625 : speed < 0 ? speed + 0.0625 : 0;

## When to use it

When movement should have weight: a hero who takes a moment to get going and slides a little when you let go, ice or mud that feel different from grass, a ship that drifts. When you want instant, exact control, as in most puzzle games, set the position straight from the D-pad, like [the vectors page](/math/vectors/) does.

## How to think about it

**The velocity is what the hero keeps between frames.** The D-pad no longer moves the hero. It changes the velocity a little, and the velocity moves the hero. So `velocity` lives outside the loop, and each frame does two additions:

**Acceleration and friction are two speeds of change.** Holding a direction, the velocity grows by the acceleration each frame until it reaches the top speed. Letting go, it shrinks by the friction each frame until it reaches 0. Big numbers feel snappy, small ones feel slippery.

## The smallest thing that works

The **D-pad** walks the hero, on the grass on the left or the sand on the right. Let go, and the bottom line says how far the hero slid and for how many frames. **A** turns inertia off, so the hero moves at full speed at once and stops dead.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `template<typename Number> Number approach(...)` | A function template: the compiler writes one version for each type you call it with. Here it's only `bn::fixed`, but the same code works for `int`. |
| `constexpr surface grass = { "Grass", 1.5, 0.125, 0.0625 };` | The numbers that make the feel, in one place, with names. Tuning the game means editing this line. |
| `const surface& ground = ... ? sand : grass;` | A reference to one of the two, chosen each frame. Nothing is copied. |
| `const surface* shown_surface` and `&ground != shown_surface` | A pointer remembers which surface the text shows, so the text is only rebuilt when it changes. `nullptr` means nothing shown yet. |

## Pitfalls

**The speed never reaches 0.**
Subtracting the friction without stopping at 0 passes 0 and comes back. Starting from a diagonal speed of 1.05468 with a friction of 0.0625, the speed ended up jumping between 0.05468 and -0.00781 forever. Use a step that can't pass its target, like `approach`.

**Friction by multiplication depends on rounding.**
`velocity *= 0.9` looks natural, but with `bn::fixed` its end depends on how the multiplication rounds. From 1.5, `*` stopped in 27 frames after 10.6 pixels, because it drops low bits. `safe_multiplication` kept tiny speeds alive for 66 frames. Subtracting a fixed step, as the snippet does, stops when you expect.

**The diagonal is faster.**
If each axis approaches the top speed on its own, the diagonal gets 1.5 on both axes, 2.12 in all, as [the vectors page](/math/vectors/) measured. The snippet makes the target from a direction of length 1, then approaches it axis by axis.

**"Not enough space: 33 - 32".**
The first version of this snippet stopped with that error from `bn_string.h` as soon as the speed reached three digits. The number in `bn::format<32>` is the most characters the text can have, and "Grass  Pixels per 100 frames: 150" is 33. Count the longest text you can show.

**"Invalid value: -170103" in `bn::sqrt`.**
The first version also measured the stopping distance times 100, through `squared * 10000`. A 17-pixel slide squared is 289, times 10000 is far past 524287, the most a `bn::fixed` holds, and it came out negative. The snippet keeps that trick for speeds, which stay small, and measures distances in whole pixels.
