export const rad = (degrees) => (degrees * Math.PI) / 180;
export const polar = (center, degrees, length) => ({
	x: center.x + Math.cos(rad(degrees)) * length,
	y: center.y + Math.sin(rad(degrees)) * length,
});
export const wedge = (center, from, to, length) => {
	const a = polar(center, from, length);
	const b = polar(center, to, length);
	return `M ${center.x} ${center.y} L ${a.x} ${a.y} A ${length} ${length} 0 ${to - from > 180 ? 1 : 0} 1 ${b.x} ${b.y} Z`;
};
// Figure 1: the three checks, in figure units.
export const eye = { x: 60, y: 90 };
export const cone = 125;
export const seenHero = polar(eye, -12, 100);
export const blockedHero = polar(eye, 15, 108);
export const blockedCrate = { x: 118, y: 97, size: 20 };
export const blockedStop = { x: 118, y: 90 + Math.tan(rad(15)) * 58 };
export const outsideHero = polar(eye, 62, 72);
// Figure 2: one ray through a grid, worked out the way cast_ray does it.
export const cell = 30;
export const grid = { x: 20, y: 12, columns: 8, rows: 5 };
export const walk = (() => {
	const start = { x: 1.4, y: 3.6 };
	const direction = { x: Math.cos(rad(-25)), y: Math.sin(rad(-25)) };
	const crate = { x: 6, y: 1 };
	let column = 1;
	let row = 3;
	let nextX = (column + 1 - start.x) / direction.x;
	let nextY = (start.y - row) / -direction.y;
	const cells = [{ x: column, y: row }];
	const crossings = [];
	while (!(column === crate.x && row === crate.y)) {
		let travelled;
		let axis;
		if (nextX < nextY) {
			travelled = nextX;
			nextX += 1 / direction.x;
			column += 1;
			axis = 'x';
		} else {
			travelled = nextY;
			nextY += 1 / -direction.y;
			row -= 1;
			axis = 'y';
		}
		crossings.push({ axis, x: start.x + direction.x * travelled, y: start.y + direction.y * travelled });
		cells.push({ x: column, y: row });
	}
	return { start, crate, cells, crossings };
})();
export const gx = (x) => grid.x + x * cell;
export const gy = (y) => grid.y + y * cell;
// Figure 3: the cone test with a dot product.
export const dotCenter = { x: 60, y: 110 };
export const dotLength = 140;
export const dotRays = [
	{ degrees: -18, color: '#2f9e36', label: 'cos 18° = 0.951: seen' },
	{ degrees: -38, color: '#ff4d8d', label: 'cos 38° = 0.788: not seen' },
];
// Pitfall: the joint between two crates, in room pixels.
export const joint = { left: 136, top: 24, scale: 3 };
export const jx = (x) => 20 + (x - joint.left) * joint.scale;
export const jy = (y) => 10 + (y - joint.top) * joint.scale;
export const jointCrates = [{ x: 144, y: 32 }, { x: 160, y: 48 }];
export const jointSamples = [40, 48, 64, 72].map((t) => ({ t, x: 120 + t * Math.SQRT1_2, y: 88 - t * Math.SQRT1_2 }));
// Pitfall: the cone without dividing by the distance, widest angles measured in the test ROM.
export const rawCenter = { x: 40, y: 100 };

## When to use it

When an enemy should react to the player only if it could plausibly see them: a guard in a stealth game, a turret that fires when you're in the open, a monster that notices you around a corner but not through a wall. Distance alone isn't enough, because walls and facing matter.

## How to think about it

**Seeing is three checks, cheapest first.** Is the hero close enough? Is the hero inside the cone the sentinel faces? Is there nothing solid on the line between them? The first two are a little math. The third walks the map, so it runs only when the first two pass.

**A ray walks from grid line to grid line.** The map is a grid of 16-pixel cells, and something only blocks the view if the line enters its cell. So instead of testing points along the line, the ray jumps from one cell to the next. From where it is, it works out how far along the ray the next vertical grid line is, and the next horizontal one, and steps to whichever is nearer. Vertical lines come at equal distances along the ray, `every_x`, and so do horizontal ones, `every_y`, so each step is one addition.

**The cone is a dot product.** Make both the facing and the direction to the hero length 1. Then multiply their x's, multiply their y's, and add: that's the dot product, and it's the cosine of the angle between them: 1 straight ahead, 0 to the side, negative behind. Inside a 50-degree cone means at most 25 degrees off, so the test is `cosine >= cos(25°)`, 0.9063, with no angle to work out at all.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `cosine >= half_cone_cos && cast_ray(...) >= distance` | `&&` stops at the first `false`, so the ray is only cast for a hero inside the cone. The order of the checks is the order of their cost. |
| `bn::span<bn::sprite_ptr>` and `subspan(...)` | One vector of 24 sprites, seen as three rays of 8 without copying anything. `show_ray` doesn't care which of the three it got. |
| `.safe_division(...)` instead of `/` | `/` keeps only half of the divisor's bits, so a direction close to an axis stops the game. See the pitfalls. |
| `toward.x().safe_multiplication(facing.x())` | Plain `*` also drops bits. With the sentinel facing 40 degrees, the measured edge of the cone was 63 degrees with `*` and 65 with `safe_multiplication`, the right answer. |
| `direction * along` with `int along` | A `bn::fixed_point` times an `int` is exact. Times a `bn::fixed`, it would round the same way `*` does. |
| `bn::pair<bn::fixed, bn::fixed> sin_and_cos` | Two values from one call: `.first` is the sine, `.second` the cosine. |

## Pitfalls

**"32bit integer division by zero detected".**
The first version of `cast_ray` used `/`, and stopped with that message in its first second, when the cone's edge passed horizontal. The edge was 0.5 degrees off the axis, and its y, 0.0087, isn't 0, so the `!= 0` check let it through. But `bn::fixed`'s `/` cuts the divisor down to half its bits first, and anything under 1/64 becomes 0: in the test ROM, dividing by 63/4096 stopped the game and 64/4096 didn't. Just above that, `/` is still wrong: 16 divided by 0.0244 gave 1024 instead of 655.36. `safe_division` does the division in 64 bits.

**Stepping along the line sees through corners.**
Testing a point every few pixels looks simpler than walking the grid. Over every place the hero can stand within range, 17325 of them, points 1 pixel apart saw the hero through a crate from 51 places, 4 pixels apart from 137, and 8 pixels apart from 276. Some of those are on the diagonal past the two crates that touch at a corner, top right of the sentinel: the line goes exactly through the corner, and no point lands inside either crate. `cast_ray` stops there, at 56.57 pixels. Stepping 1 pixel was also 9 times slower: 199 timer ticks per ray against 23, out of 4389 in a frame.

**The cone grows with distance.**
Leave out the division by the distance, and the dot product is the cosine times the distance. The test ROM, facing right, still asked for 0.9063: the cone was 25 degrees on each side with directions of length 1, but 86 degrees for a hero 16 pixels away, and 89 at 50 and 90 pixels. The sentinel saw nearly everything in front of it.

**Many sentinels, many rays.**
At 23 ticks a ray, a frame has room for about 190 of them and nothing else. The snippet casts three, and only one of them decides anything. If many enemies look every frame, cast the hero ray only after the cheap checks pass, or look every few frames.
