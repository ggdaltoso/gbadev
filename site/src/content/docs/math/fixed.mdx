## When to use it

Any time a value needs a fraction: positions, speeds, angles, timers that grow by less than one per frame. Butano already uses `bn::fixed` for positions, so most of your math will be in it too. Use `int` when the value is truly whole, like a count or an index.

## How to think about it

**The GBA has no hardware for fractions.** Its CPU only does integer math. A `float` still compiles, but each operation becomes a small function that does the work with integers, and that's slow.

**`bn::fixed` is an `int` that counts 4096ths.** It keeps a single `int`, which it calls `data()`. The value is `data() / 4096`, so 1.5 is stored as 6144, and the smallest step is 1/4096. Adding two of them is adding two `int`s, which is as fast as it gets.

**Multiplying and dividing need care.** Multiplying two 4096ths gives 4096×4096ths, which has to be scaled back down, and the middle step can overflow an `int`. Butano's `*` avoids that by dropping some precision first. Division is the slow one: the GBA has no instruction for it.

**Sine and cosine come from a table.** `bn::degrees_lut_sin_and_cos` looks the answer up in a table built into Butano, in `bn::fixed`. No series, no `float`.

## Pitfalls

**0.1 added ten times isn't 1.**
0.1 is stored as 409/4096, a little less than 0.1. Ten of them are 4090/4096, so `sum == 1` is `false`. Count in whole steps when you need an exact result, such as frames instead of seconds, and compare with `>=` instead of `==`.

**A small number times a small number gives 0.**
`bn::fixed(0.01) * bn::fixed(0.5)` is 0, because `*` drops the lowest 6 bits of each value first to avoid overflow, and 0.01 doesn't survive that. `safe_multiplication` keeps the precision: it gave 20/4096, about 0.005.

**A big number times a big number is garbage.**
`bn::fixed(1000) * bn::fixed(1000)` gave -48576. The result has to fit in about ±524287, and a million doesn't, so `safe_multiplication` doesn't help either. Keep big values in `int`, or scale them down.

**Dividing every frame, for every object.**
1000 divisions took over half a frame. When you divide by the same number many times, divide once and multiply by the result.

**-1.5 becomes -1.**
`integer()` drops the fraction toward zero, so -1.5 gives -1. `floor_integer()` gives -2, and `round_integer()` gives -2 too. See [map collision](/basics/collision/) for where that bites.

**"Angle must be in the range [0..360]".**
`bn::degrees_lut_sin` and its family stop the game outside that range. Wrap the angle yourself, as the snippet does, or use the `_safe` versions, which wrap it for you.

**Text shows 0.75000.**
`bn::format` prints a `bn::fixed` with five decimals. To print fewer, format the parts yourself, for example `(value * 100).round_integer()`.
