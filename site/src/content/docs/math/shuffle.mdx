## When to use it

When random has to feel fair: the next piece in a falling-block game, which enemy comes out of the door, what a chest drops. Plain random has no memory, so sooner or later the same thing comes up four or five times in a row, and the player feels cheated. A shuffle bag still surprises, but it can't do that.

It builds on [Timers and random numbers](/basics/timers/), for `bn::random` and seeds.

## How to think about it

**Plain random has no memory.** Each `get_int(4)` has a 1 in 4 chance of giving the same kind as the last one, whatever came before. A streak of three is a 1 in 16 chance at any draw, and over hundreds of draws long streaks are sure to happen. In the snippet, plain random's longest streak was 5 after 147 draws, and still 5 after 1175. The bag next to it never went past 2.

**A shuffle bag is a deck of cards.** Put every kind in, `copies` times each: 4 kinds, 2 copies, 8 tokens. Shuffle, then take them out one at a time. When the bag is empty, fill it and shuffle again. Every 8 draws, each kind has come out exactly twice. Inside a bag the two copies of a kind can come out together, but never three.

**The seam between two bags needs a look.** The old bag can end with two candies, and the new one, shuffled on its own, can start with two more: four in a row, across the seam. So after shuffling, `refill` compares the token that comes out first with the last one drawn. If they're the same, it swaps another kind into that place. With that check, the longest streak is two, and the snippet never showed more in 1175 draws.

Some of the C++ in the snippet:

| In the code | Why |
|---|---|
| `bn::swap(_tokens[index], _tokens[random.get_int(index + 1)]);` | Fisher-Yates. Going down from the end, each place swaps with any place up to and including itself. `get_int(index + 1)` goes from 0 to `index`. |
| `for(int index = 0; _tokens[bag_size - 1] == _last; ++index)` | A loop that's only a condition: keep swapping until the first token out differs from the last one drawn. With more than one kind it always ends. |
| `int _tokens[bag_size] = {};` | A plain array as a class member, filled with zeros. `= {}` gives the members a value before the first `refill`. |
| `explicit row(int y)` | `explicit` stops an `int` turning into a `row` by accident, as in `row r = 36;`. |
| `text.shrink(fixed_text);` | Drops the text sprites past the hint, so only the counters are rewritten. |

## Pitfalls

All three test ROMs were run with A held for 20 seconds, about 1175 draws, like the snippet. The pictures are their last frames.

**Without the check, streaks cross the seam.**
A test ROM without the swap at the seam reached a longest streak of 3 in the bag row, where the snippet stayed at 2. With two copies, four in a row is possible: two at the end of one bag and two at the start of the next (worked out, not seen in this run).

**A big bag is plain random again.**
A test ROM with 20 copies of each kind, an 80-token bag, reached a longest streak of 4. Inside a big bag, the copies of a kind can bunch up, just like plain random. A small bag is fairer, and 1 copy of each would never repeat at all. But then the last draw of each bag can be guessed from the three before it (worked out, not tested).

**A new `bn::random` every draw gives the same number every time.**
A test ROM that drew with `bn::random().get_int(kinds)`, a new generator for each draw, drew the burger 155 times in a row, every single draw. A new `bn::random` always starts from the same state, so its first number is always the same. Keep one generator and let it run.
