# CLAUDE.md

How this guide is built and how to work on it. README.md has the public rules and the roadmap; this file has the working process.

## Working with the owner

- The owner writes in Portuguese: reply in Portuguese. Pages, code, comments and commit messages are in English.
- One lesson at a time. When a lesson is done, report it in Portuguese (topic, figures, pitfalls and what was measured, errors fixed, what wasn't checked) and ask "Quer commit e push?".
- On a yes: commit and push straight to `main`, then go on to the next lesson.
- Need art the pack doesn't have? Ask the owner for CC0 art instead of bending the example to fit.

## Scope

A general guide to making GBA games with Butano, not tied to gg-game: any topic is fair game, including the ones the owner's game needs. Examples are still written for the guide, not copied from gg-game.

## Snippets

- One ROM per folder: `snippets/<name>/` with `src/main.cpp`, `graphics/` (bmp + json) and a `Makefile` that only includes `../butano.mk` (copy `snippets/collision/Makefile`).
- Every snippet must build: `make -j8` in its folder. The `.gba` files are committed, because Netlify can't build them and the site runs them.
- **Shared art:** `snippets/common/graphics/` (not a ROM) is added to every snippet by `butano.mk`. That's where the shared hero lives, `hero.bmp`, built by `snippets/tools/hero_sheet.py`; its docstring lists the frames. Never put a `hero.bmp` in a snippet's own `graphics/`: the names would clash.
- **Shared code:** `snippets/common/include/` is added to every snippet's includes. `hero_walk.h` animates the hero's walk (facing and walk frames). Use it where the hero only walks; where the hero *is* the lesson (states, hitstop, sprites, velocity...), keep the code in `main.cpp`. A page whose snippet uses it shows the header in a `<details>` block right after the main code.
- Art is generated by a script in `snippets/tools/<name>_assets.py` from `assets/` (CC0 only). The script's docstring says what it makes and from what.
- Butano headers are in `~/projects/butano/butano/include` and its sources in `.../src`. Read them before claiming how something works.
- A snippet's `main.cpp` is shown whole on its page, so keep it short, complete and readable top to bottom, with comments only for the why.

## Pages

Pages live in `site/src/content/docs/<section>/<name>.mdx`. Each one has five sections:

1. **When to use it.**
2. **How to think about it:** one bold mental model per paragraph, each with a figure (inline SVG, or images in `site/public/images/<name>/`).
3. **The smallest thing that works:**
   - the code (`<Code code={...} />` from `?raw`);
   - a demo GIF;
   - `<Rom name="..." />`;
   - a "Some of the C++ in the snippet" table;
   - art credits.
4. **Pitfalls:** each one measured in a probe ROM (`snippets/_t_*`), with the symptom actually seen. Delete the probes afterwards, and their copies in `site/public/roms/`.
5. **Read more:** Butano examples and headers, Tonc, cppreference, other guide pages. Check every link with curl.

**Genres:** a page that suits one kind of game best says so in its frontmatter, `genres: [shooter]` (at most two). A page that suits any genre has no `genres`. The list, with each one's icon and color, is `site/src/genres.ts`; the schema rejects anything else. The icons show next to the page in the sidebar (`site/src/routeData.ts`), under its title (`site/src/components/PageTitle.astro`) and in the legend on the home page.

Writing rules:

- **Claims:** say what was measured and what was only worked out. Don't state anything you didn't check.
- **MDX:**
  - Don't put `//` comment lines between top-level exports.
  - Put text like `<12>` in backticks.
- **Colors for figures:** blue `#1e7cb8`, green `#2f9e36`, pink `#ff4d8d`. Use `currentColor` for text, so both themes work.
- **GIFs:** 50 ms per frame. Use a shared 64-color palette, and save at 1x when 2x gets too big (around 600 KB or more).

## Checking a lesson

- `cd site && npm run build` must end with `Complete!`. Copy new ROMs to `site/public/roms/`, or run `npm run -s static`.
- Open the page in the owner's Edge through the Chrome extension, in the light theme. Check every figure and the Run button, then close the tab.
- Don't mention the dark theme in reports, not even as "not checked". The owner will say when it's a problem.
- Update README.md:
  - add the numbered item in the right section;
  - update the status line ("the first thirty-N pages are live...").

## Butano facts that bit us (21.9.0)

- **`bn::fixed` arithmetic:**
  - `/` uses half precision, so a divisor under 1/64 is a division by zero. Use `safe_division`.
  - `fixed * fixed` loses precision; `safe_multiplication` doesn't. `fixed * int` is exact.
- **Rounding:** sprites and backgrounds are drawn at their position rounded down (`shift_integer`). `integer()` truncates toward zero.
- **`bn::seed_random`:** consecutive seeds give shifted sequences, so spread them out (`seed * 1024`).
- **Sprite order:**
  - a higher `z_order` is drawn behind, and `bg_priority` beats `z_order`;
  - on a tie, the newest sprite is on top;
  - there are 16 sort layers.
- **Sizes:**
  - sprites go up to 64x64;
  - regular backgrounds go up to 512x512 in hardware, and bigger ones are "big" maps (multiples of 256, never compressed, at most 1024 different tiles).
- **Windows:** Butano clamps window boundaries to the screen.
